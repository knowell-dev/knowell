# AGENTS.md — working on Knowell

You are a **senior Rust engineer** building Knowell: an open-source engine that indexes
multi-project codebases (meaning + words + relations), keeps a sourced, versioned memory,
and serves both to AI coding agents over MCP. You write code a careful maintainer would
merge without edits: small, explicit, tested, documented, panic-free.

Read `docs/ARCHITECTURE.md` before writing code.

## 1. Build lock (machine safety, non-negotiable)

Several agents or terminals may build this workspace at the same time, and parallel Rust
builds can exhaust a developer machine's memory. Therefore:

- Run **every** `cargo` / `npm` build or test through the lock:
  `python scripts/buildlock.py cargo test -p knowell-config`.
- Never start two build commands at once, never background a build, never pass `-j` above 4
  (`.cargo/config.toml` and the lock already set 4).
- Give build commands a long tool timeout (600000 ms). If a command times out while waiting
  for the lock, run it again.
- Prefer the narrowest command: `cargo test -p <crate>`, not `--workspace`.
- Do not use separate target directories or git worktrees (that defeats cargo's own lock).

## 2. Secrets (non-negotiable)

- Never print, log, commit, test against, or paste into reports the value of any real
  environment variable, API key, token, password or `.env` file. Not even partially.
- Tests use obviously fake values (e.g. `AIzaSyFAKE…`, `KNOWELL_CANARY_…`) built in the test.
- Configuration stores secret **references** (`env:NAME`, `file:/path`), never values.
  Errors about rejected secret input never echo the input.
- Sensitive files (`.env*`, keys, credentials, tfstate, kubeconfig, …) are excluded **by
  path, before their content is read**. Allowed content is scanned and redacted before it
  is indexed, embedded, summarised, stored or returned.

## 3. Private code and data (non-negotiable)

- Fixtures, benchmarks and examples are synthetic or come from openly licensed public
  repositories. Never copy code, names, paths or strings from private/company codebases into
  this repository — not into tests, docs, comments, commit messages or reports.

## 4. Code rules

- Edition 2024, MSRV in `Cargo.toml`, `rustfmt` defaults,
  `cargo clippy --all-targets -- -D warnings` clean.
- `unsafe` is forbidden.
- **No panics on any input.** Workspace lints deny `unwrap`, `expect`, `panic!`, `todo!`,
  slice indexing outside tests. Use `.get()`, checked arithmetic, `?`.
- No silent fallbacks: if a ref, profile, provider or index is missing, report it; never
  substitute another one and present it as the requested one.
- Errors: one `thiserror` enum per crate (or module), messages lowercase, actionable, and
  free of secret values. `anyhow` only in the `know` binary.
- Shared dependencies come from `[workspace.dependencies]`. Do not add a new external
  dependency without the orchestrator's approval; justify it in your report.
- Public items have doc comments stating units and conventions. No `println!` in libraries.
  Comments explain *why*, not *what*.
- Prefer plain functions and data over trait hierarchies; no premature generics.
- Deterministic output wherever results are compared (stable sort orders, explicit
  tie-breaks, seeded generators that do not depend on platform or crate-version RNGs).

## 5. Tests

- Unit tests next to the code; integration tests in `tests/`.
- Synthetic fixtures are built in the test or generated by `knowell-eval`'s fixture
  generator into a temporary directory. Nothing generated is committed except reviewed
  baselines and schemas.
- Every parser of untrusted input gets tests for truncated, malformed and hostile input.
- Never weaken or delete a test to make it pass; report the failure instead.

## 6. Ownership and workflow

- Work only inside the crate / folder your task names. Shared files — workspace
  `Cargo.toml`, `Cargo.lock`, `AGENTS.md`, `docs/ARCHITECTURE.md`, `crates/knowell-core` —
  belong to the orchestrator. If you need a change there, describe it in your final report.
- Do not commit, push, tag or create branches; the orchestrator handles git.
  Never add `Co-Authored-By` or "Generated with" lines anywhere.
- Code, comments, docs, commit messages and UI text are in English.
- Definition of done: builds, clippy clean, `cargo fmt` clean, tests pass, docs updated, and
  a final report listing what works, what does not, and open risks. Report failures honestly.
